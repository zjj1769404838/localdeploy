## 事实底座（实查/实测，2026-11-17）
- 调研来源：[クロスマート Electron vs Tauri vs Wails 同项目实测](https://xmart-techblog.hatenablog.com/entry/2025/09/01/110000)（体积 70-150/5-15/10-20MB，启动 Tauri≤Wails<<Electron）；[CSDN Windows 轻量客户端三方案](https://www.csdn.net/detail/webblog_38637020/35450)（Wails 15.2MB/710ms vs Electron 112MB/2.4s；决策树：Go 团队→Wails，前端团队→Tauri/Electron）。
- 本机实测（pwsh）：node v22.19.0 ✓、npm 10.9.3 ✓（需 cmd /c 绕执行策略）、git 2.47.1 ✓；**go/rustc/gcc 全部未安装**；WebView2 Runtime 三处标准路径缺失（msedge.exe 存在）；OS Windows 11 Home China。
- mkcert：GitHub Releases 实测最新 v1.4.4（2022-04-26），BSD-3，提供 windows-amd64 预编译。
- 历史教训（仅作事实输入）：hosts 写入需管理员，普通权限失败须降级警告不阻塞（旧项目实测曾致 500）；端口占用回退机制曾实测有效——但本次用户改选「冲突仅提示」。

## 决策清单
| # | 决策点 | 结论 | 依据/备注 |
|---|--------|------|----------|
| D1 | 产品形态 | 真桌面窗口 + 托盘辅助 | 用户原始诉求「exe 桌面程序」 |
| D2 | 托管范围 | 已构建产物：静态 dist + 命令式后端进程；不做构建流水线 | 控制 v1 复杂度 |
| D3 | 引擎语言 | Node.js（与 Electron 同栈） | 本机唯一现成工具链 |
| D4 | **桌面框架** | **Electron** | go/rust 缺失 + WebView2 缺失 → Tauri/Wails 需数 GB 工具链与新依赖；Electron 今天可开工；体积 ~100MB 代价换环境确定性；管理工具非高频交互内存不敏感 |
| D5 | 访问入口 | 自定义域名 `<slug>.zjj` + 端口直连双通道 | 用户主动推翻纯端口方案 |
| D6 | 分发范围 | 自用，绿色版为主，无自动更新 | 零成本原则 |
| D7 | 数据落盘 | `%APPDATA%\LocalDeploy\`；应用本体未来装 `D:\apps` | Windows 惯例 + 用户既有约定 |
| D8 | 命名 | LocalDeploy | 沿用旧名（语义无涉旧实现） |
| D9 | 前端栈 | Vue3 + Vite + TS + Naive UI（MIT） | 用户前端背景；组件库免费 |
| D10 | 崩溃策略 | 指数退避 1s→30s，连败 5 次 crashed，手动复活 | 防重启风暴 |
| D11 | 自启 | HKCU Run + 启动拉起，双开关默认关 | 无管理员；首装不打扰 |
| D12 | 日志 | 环形 2000 行 + 5MB×3 滚动 + 实时 tail | 够用即可 |
| D13 | SPA 回退 | 每项目开关默认开 | history 路由刚需 |
| D14 | 反代网关 | v1 内置（域名需求的逻辑依赖，从原 v2 提前） | 按 Host 分流 |
| D15 | 打包 | portable 单 exe 为主 + NSIS；**不签名** | 签名 ~$500/年违反零成本；SmartScreen README 说明 |
| D16 | 验收 | Vitest 核心全覆盖 + e2e 演练 + 独立审核 | 团队教义：审核者≠执行者 |
| D17 | hosts 路线 | hosts 文件；按需 UAC 提权一次；失败降级警告不阻塞 | DNS/PAC 方案风险更大；旧坑验证 |
| D18 | 域名后缀 | `.zjj`（用户自定义，勾选 Other 填入） | 用户选择；设置页可改 |
| D19 | 网关端口 | 用户可配置；默认 80/443；**冲突仅提示不回退**（推翻推荐） | 用户勾选明确选了「仅提示」 |
| D20 | HTTPS | v1 要（推翻推荐）；**mkcert 外部工具**（推翻纯 JS 推荐）；全局总开关默认关 | 用户勾选 |
| D21 | mkcert 集成 | 构建期捆绑 mkcert.exe v1.4.4 进资源目录，CAROOT 隔离 | 离线可用零手动 |
| D22 | 协议策略 | HTTPS 开启时 80→443 301；单张 `*.zjj` 通配符证书 | 推荐通过 |
| D23 | 添加项目 | 智能向导自动识别类型预填 | 体验总纲「能自动的不手填」 |
| D24 | 配置化 | 全量配置可视化 + config.yaml 双通道热加载 | 用户「尽可能配置化」 |
| D25 | 主界面 | 项目卡片仪表盘 + 日志抽屉 + 全局操作栏 | 零学习成本 |
| D26 | 首启引导 | 轻量三步（欢迎/域名·HTTPS/添加项目），可跳过 | 不打扰原则 |

## 体验总纲（用户原话，凌驾实现细节）
「尽可能让用户用的简单、交互友好、尽可能配置化」→ 提炼为：**能自动的不手填、能默认的不追问、能配置的不写死、权限失败不阻塞**。

## 变更规程
任一 D# 变更：先改本文 → 同步 docs/01~03 → 改代码与测试断言；不可逆交付动作（push/publish/邮件）各自独立授权。
