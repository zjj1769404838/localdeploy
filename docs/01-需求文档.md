# 01 需求文档 — LocalDeploy v1

## 1. 产品定位
Windows 自用桌面工具（exe），在本地一键部署并守护**前端构建产物**与**后端项目进程**，通过自定义本地域名（`<项目名>.zjj`）+ 可选 HTTPS 统一访问。设计原则：**能自动的不手填、能默认的不追问、能配置的不写死、权限失败不阻塞**。

## 2. 用户与场景
- 单一用户（本机 Windows 11 Home China），自用，无多用户/权限体系。
- 场景：手上多个前端（Vue/React 构建产物或 dev server）与后端（Node/Java/Python/Go 等任意可命令行启动的进程）项目，希望开机后用统一入口管理：启停、看日志、崩溃自动拉起、浏览器用 `myapp.zjj` 访问。

## 3. 功能需求（FR）
| ID | 需求 | 优先级 |
|----|------|--------|
| FR-1 | 项目管理：添加/编辑/删除项目；添加走智能向导——选择目录后自动识别类型（存在 dist/build/out → 静态站点；存在 package.json → 预填 `npm start`；jar → `java -jar`；main.py → `python`；可编辑修正），域名自动生成（项目名转小写连字符 + `.zjj`），用户确认即建 | P0 |
| FR-2 | 静态托管：伺服指定目录静态文件；「SPA 模式」开关（默认开）：未命中文件回退 index.html | P0 |
| FR-3 | 进程守护：按命令+工作目录+环境变量启动子进程；捕获 stdout/stderr 入日志；停止杀整棵进程树 | P0 |
| FR-4 | 崩溃自动重启：指数退避 1s→2s→4s…封顶 30s；连续失败 5 次标记 `crashed` 停止重试；界面亮红；手动可复活（重置计数） | P0 |
| FR-5 | 反代网关：按请求 Host 头分流到各项目上游（静态服务内置、后端进程端口）；域名未配置的项目仍可端口直连 | P0 |
| FR-6 | 本地域名：勾选后写 hosts `127.0.0.1 <domain>`；删除项目清理对应行；hosts 由本工具托管专用区块（begin/end 标记） | P0 |
| FR-7 | 提权与降级：hosts 写入需要管理员时自举 UAC 一次完成；**任何权限失败降级为警告，不阻塞项目创建/运行**（域名访问不可用但端口直连可用），界面琥珀色明示 | P0 |
| FR-8 | HTTPS：全局总开关（默认关）。开启时经内置 mkcert 安装根 CA（按需 UAC）并签发 `*.zjj` 通配符证书；网关 443 提供 https，80 收到域名请求 301 跳 https；失败降级回 HTTP 并警告 | P1 |
| FR-9 | 日志：每项目环形缓冲最近 2000 行（界面实时 tail）+ 落盘滚动（单文件 5MB×3 份）；历史查看、一键清空 | P0 |
| FR-10 | 设置页：全部行为参数可视化编辑（网关端口、域名后缀、退避参数、日志参数、自启开关、HTTPS 开关等），每项带默认值与一句话说明；改动即时生效 | P0 |
| FR-11 | 配置双通道：`%APPDATA%\LocalDeploy\config.yaml` 可直接编辑，文件变更热加载 diff 应用（改端口→网关重绑、改项目→增删改同步）；UI 改动亦写回该文件 | P0 |
| FR-12 | 开机自启（默认关）：HKCU Run 键写入，无管理员；「启动时自动拉起项目」（默认关）：按项目 `autoStart` 标记逐个拉起 | P1 |
| FR-13 | 窗口/托盘：真桌面主窗口；关窗最小化到托盘，托盘菜单（打开/全部启停/退出）；服务在窗口隐藏后持续运行 | P0 |
| FR-14 | 首启三步引导：欢迎→可选启用域名/HTTPS（说明将弹 UAC，可跳过）→添加第一个项目；完成或跳过后不再打扰 | P2 |
| FR-15 | 状态恢复：应用重启后按各项目 `desired` 状态恢复运行 | P1 |

## 4. 非功能需求（NFR）
| ID | 需求 |
|----|------|
| NFR-1 | 依赖全免费开源（MIT/BSD/Apache 类）；零付费服务、零云依赖 |
| NFR-2 | 日常运行不需要管理员权限；仅 hosts 写入与根 CA 安装按需 UAC，且失败可降级 |
| NFR-3 | 凭据零落盘：本项目不含任何密钥；GitHub/邮箱凭据仅经环境变量或 CLI 参数 |
| NFR-4 | 空闲资源：主进程+窗口常驻内存预期 <300MB（Chromium 底座） |
| NFR-5 | 交付：portable 单 exe 为主（双击即用）+ NSIS 安装包；不签名（README 说明 SmartScreen 处理） |
| NFR-6 | 测试：核心引擎 Vitest 单测；端到端演练只用非特权端口与临时目录 hosts 桩，禁碰真实系统路径 |

## 5. v1 明确不做（Out of Scope）
构建流水线（npm install/build）、Docker、远程/多机部署、公网域名与 Let's Encrypt、多用户、代码签名、应用内自动更新、统一路径分流网关（已被域名网关取代）、按项目 HTTPS 开关（仅全局）。

## 6. 验收标准（DoD）
1. Vitest 核心引擎单测全绿（实跑记录退出码）。
2. 端到端演练通过（drill/e2e.mjs，非特权端口）：创建静态+后端项目 → 域名解析路径（桩）→ HTTP 访问 200 → kill -崩溃 → 自动重启 → 手动停止 → 日志可见 → 重启应用状态恢复。
3. hosts 权限拒绝场景：降级警告、项目仍可端口直连、界面琥珀色提示（演练断言）。
4. 独立审核报告（审核者≠执行者）无 blocker 项。
5. GitHub 仓库 + Release 产物可下载，SHA-256 与文档一致（多通道核验）。
6. 下载链接邮件送达用户邮箱（独立读回验证）。
